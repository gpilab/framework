# Voxel Starter Examples

Author: Guru Krishanmoorthy  
Date: Nov 2026

These examples use short C++ functions, direct NumPy-to-Voxel bindings, and
straightforward GPI nodes. Start with concrete types; read the template
functions last. No `py::arg` settings or manual NumPy casts are needed.
The `.pyi` files are generated by `gpi_make`; do not edit them manually.

## Two nodes, not a node for every operation

- [Scale](GPI/Scale_GPI.py) and [voxel_scale_bind.cpp](voxel_scale_bind.cpp):
  the smallest copy/in-place introduction.
- [ArrayBasics](GPI/ArrayBasics_GPI.py) and
  [voxel_basics_bind.cpp](voxel_basics_bind.cpp): seven walkthrough functions
  combining related operations on multidimensional arrays.

Build with `gpi_make --all` in this directory, restart GPI, and select
**Library > Scan For New Nodes**. The nodes appear under
the **Voxel examples** in the core node library. Both work without input. Open the GPI console for
full result arrays and labelled C++ `std::cout` messages.

## ArrayBasics walkthrough

Read the C++ functions in order. Each groups several related capabilities,
rather than defining a separate example for every individual operation.

| Function | What it covers | Node output |
| --- | --- | --- |
| `integer_1d()` | Zeros, indexing, a simple loop, ones, copying, in-place addition/multiplication, sum/min/max | `integers`: `[4, 6, 8, 10, 12, 14]` |
| `real_2d()` | Linspace, reshape, a shared slice, transpose, vector-to-matrix broadcasting, flatten, mean/stdev | `real2d`: `[[11, 12, 13], [4, 5, 6]]` |
| `complex_3d()` | A 2x2x2 array, fill, real/imaginary components, magnitude, phase, conjugate | `complex3d`: every element is `3 - 4j` |
| `matrix_2d()` | Element-wise versus matrix multiplication, Cholesky solve, SVD, PCA | `matrix`: `[[5, 11], [11, 25]]`; other results are printed in C++ |
| `fft_example(input, inverse)` | Forward/inverse FFT across all dimensions | `spectrum`, `inverse_fft` |
| `wavelet_example(input, threshold)` | One-level 2D Haar analysis, soft thresholding, and reconstruction | `wavelet`, `denoised` |
| `array_template(input, factor)` | Copy, add, multiply, and reductions for N-dimensional float/double arrays | `out1 = (input + input) * Factor` |

The template is last. The GPI node uses explicit calls in the same order:
no function tables, dispatch loops, manual casts, or custom binding classes.
Array creation happens inside the C++ walkthroughs as well as in the Python
FFT/wavelet sample inputs.

### Input and output

Optional `in1` accepts any non-empty, native float32/float64 array, including a
scalar or arrays with more than three dimensions. It is used by the final
template example only. With no input, the node creates a 2x2x2 float32 array
containing `1` through `8`. **Factor** defaults to `2`.

The other walkthroughs use small fixed inputs so the results stay easy to
follow. The node copies connected input before calling C++; it never modifies
data owned by another node. All nine output arrays are printed.

### Details worth knowing

- A slice shares its original storage. `real_2d()` deliberately changes the
  first row through a slice; `.copy()` creates independent storage.
- The linspace example explicitly includes its endpoint.
- Voxel's `stdev` uses `N - 1`, matching `np.std(data, ddof=1)` for at least two
  values. Voxel returns `0` for a single value.
- Phase is in radians.
- The matrix example uses a positive-definite matrix for Cholesky. It prints
  the solution, singular values, and PCA variances. QR is not demonstrated:
  the installed Voxel QR wrapper currently fails to compile against Eigen.
- FFT uses unshifted frequency order to match `np.fft.fftn` and
  `np.fft.ifftn`. In the C++ call, `{}` means all axes and `false` disables
  centering. The node demonstrates a 3D round trip.
- Wavelets use a one-level Haar transform. Threshold `0` reconstructs the
  original image; threshold `0.5` shrinks detail coefficients while leaving
  the coarse approximation untouched. This is a thresholding demonstration,
  not an automatic noise-estimation method.

## Scale example

A minimal example of a GPI node calling C++ through pybind11 and the Voxel
array library. It demonstrates both copying (`output = input * factor`) and
in-place scaling (`input *= factor`). The GPI node runs and prints both versions
for every example; its output port uses the copying version.
No PyTorch, CUDA toolkit, or GPU is needed.

## Files and data flow

- `GPI/Scale_GPI.py`: widgets, validation, input packing, and output ports.
- `voxel_scale_bind.cpp`: integer, float, complex, and template scaling examples.
- `test_scale.py`: numerical and node-wiring regression tests.

The node uses `data.copy()` to make a contiguous, aligned input array. The binding
uses Voxel's existing type caster to map that NumPy buffer into a
`Voxel::Array<T>` view, explicitly copies it to
independent Voxel storage, and scales the copy. Voxel's return caster exposes
the result to NumPy and keeps its storage alive.

The GPI node accepts a non-empty, native-endian `float32` or `float64` NumPy
array, including a scalar. Shape and dtype are preserved for those inputs.
The direct bindings use pybind11's default argument conversion and take
positional arguments.

## Examples: int, float, complex, then template

Read the C++ functions in source order: int, float, complex, then templates.
`using namespace Voxel;` lets the examples write `Array<T>` instead of
`Voxel::Array<T>`.
Each type has two versions:

- `scale_*` takes `const Voxel::Array<...>&`, copies, multiplies, and returns
  a new NumPy array.
- `scale_*_inplace` takes `Voxel::Array<...>&` and only runs `input *= factor`.
  It changes the original NumPy storage, makes no output copy, and returns
  `None` in Python. The template versions are `scale` and `scale_inplace`.

The caster in `Voxel/Voxel.hpp` handles NumPy input and output. There is no
manual conversion or validation code in the example functions.

For these starter examples, pass non-empty, aligned arrays with non-negative
strides. Ordinary transposes and positive-stride slices work directly.
Pack reversed arrays with `np.require(data, requirements=['C', 'A'])` before
calling the extension: the current Voxel caster uses unsigned strides.
The GPI node already handles packing and input validation.
In-place calls require writable arrays with non-overlapping elements. The
current caster does not enforce NumPy's read-only flag; do not pass read-only
arrays. Changes are visible through other views of the same storage.
Use the exact dtypes shown below for in-place calls: an implicit dtype
conversion may create a temporary instead of modifying the original array.

After building, run these with the GPI environment active. The examples are
packaged under `gpi_core.examples`; no external `gpi_examples` library is needed:

```python
import numpy as np
from gpi_core.examples.Voxel import voxel_scale

# 1. C++ int: whole numbers.
integers = np.array([1, 2, 3], dtype=np.int32)
print(voxel_scale.scale_int(integers, 2))         # [2, 4, 6]
voxel_scale.scale_int_inplace(integers, 2)
print(integers)                                 # [2, 4, 6]

# 2. C++ float: fractional values.
floats = np.array([1.0, 2.0, 3.0], dtype=np.float32)
print(voxel_scale.scale_float(floats, 0.5))       # [0.5, 1.0, 1.5]
voxel_scale.scale_float_inplace(floats, 0.5)
print(floats)                                   # [0.5, 1.0, 1.5]

# 3. C++ std::complex<float>: real and imaginary parts.
values = np.array([1 + 2j, 3 + 4j], dtype=np.complex64)
print(voxel_scale.scale_complex(values, 1j))     # [-2+1j, -4+3j]
voxel_scale.scale_complex_inplace(values, 1j)
print(values)                                  # [-2+1j, -4+3j]

# 4. C++ template: one function instantiated for float and double.
print(voxel_scale.scale(floats, 2.0))            # [1.0, 2.0, 3.0]
voxel_scale.scale_inplace(floats, 2.0)
print(floats)                                   # [1.0, 2.0, 3.0]
doubles = np.array([1.0, 2.0, 3.0], dtype=np.float64)
print(voxel_scale.scale(doubles, 0.5))           # [0.5, 1.0, 1.5]
voxel_scale.scale_inplace(doubles, 0.5)
print(doubles)                                  # [0.5, 1.0, 1.5]
```

The GPI node calls every example on small, separate sample arrays, including
both float32 and float64 template overloads. The integer example uses factor
`2`, the complex example uses `1j`, and the float and template examples use the
**Scale Factor** widget. In-place calls never modify connected input.
For direct integer calls, keep values and products within the `int32` range.
The node spells out each call in order, without a function table or dispatch
loop. It uses ordinary `print` calls and prints full node input/output arrays
as lists with `tolist()`.

## Build

Activate the same conda environment used to run GPI. Its normal C++ build
dependencies and Voxel headers must already be installed using GPI's installation
instructions. From this `Voxel` directory, run:

```shell
gpi_make --all
```

This creates platform-specific extensions and generated `.pyi` stubs beside
the binding sources. Run this command only from this example's `Voxel` directory to keep the
build scoped to this example. The `--all` form also works with older GPI wrappers
that try to treat named targets as legacy `_PyMOD.cpp` modules.

Rebuild after changing the C++ code. Restart GPI after rebuilding a
compiled extension; reloading the Python node alone does not replace native code.

## Use in GPI

1. Install GPI with its bundled `gpi_core.examples` package. The core library
   is registered automatically; no external examples library path is required.
2. Select **Library > Scan For New Nodes**, or restart GPI after installation.
3. Add **Scale** from the Voxel examples in the core node library.
4. Leave optional `in1` disconnected to generate
   `np.arange(6, dtype=np.float32).reshape(2, 3)`, or connect a non-empty
   float32/float64 NumPy source. Convert connected integer data to float first.
5. Connect `out1` to an array viewer. Open the Scale menu and change
   **Scale Factor** (default `2.0`). **Info** reports shape, dtype, and source.
6. Open the GPI console to see every example's input, factor, copy result, and
   in-place result, followed by the node's full input and output arrays.

The node executes in a GPI worker process. A missing extension produces an
explicit build instruction in GPI's log; there is no NumPy fallback.
Each C++ function also writes a labelled message using `std::cout` and
`std::endl`. GPI's worker output capture routes these messages to its console;
on Windows, `gpi_make` supplies the existing GPI iostream redirection header.

## Run import regression tests

From the framework source directory, with the GPI environment active:

```shell
python -m unittest UniTest.test_example_imports
```

Tests load the bundled examples from an isolated installed-style directory
without the external examples library or native extensions, then verify the
compute and benchmark paths import backends from `gpi_core.examples`.

You can also call the extension directly from that directory:

```python
import numpy as np
from gpi_core.examples.Voxel import voxel_scale

data = np.arange(6, dtype=np.float32).reshape(2, 3)
result = voxel_scale.scale(data, 2.0)
np.testing.assert_allclose(result, data * 2.0)
```
